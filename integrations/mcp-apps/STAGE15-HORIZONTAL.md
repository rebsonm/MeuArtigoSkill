# Stage 15 — Horizontal integrated acceptance

This phase is a synthetic, controlled engineering integration of Stages 01–14.
It does not use any real Google Drive, Auth0 tenant, registered user,
production remote host, deployment target, or human scientific decision.

## Four presentation paths
1. Local Skill workspace: `build_research_workspace.model(project=...)`.
2. Chat-native panel: `native_chat_dashboard.panel(project)`.
3. Blue website: `build_research_site.project_site_model(workspace)`.
4. One MCP Apps server: `meu_artigo_painel` tool and the
   `ui://meu-artigo/site-v1.html` resource.

The authoritative source of task IDs, native continuation decisions and
gate register counts is the canonical local project projection, never the
illustrative design mockup. An abbreviated MINIMAL snapshot MUST mark
gate views as partial: it cannot infer approvals outside the visible rows.
A FULL snapshot can display all authorized gate records. Neither
presentation independently authenticates approvals.

## Cross-component engineering contracts
- DEC/TRACE and C.A.D.A. are read-only through all visual projections.
- All seven gates require researcher decisions; method suggest, explore,
  compare, all and decision are exploratory and do not commit anything.
- REG-011/013/018/001/019 semantic advisory hints never turn into
  verified scientific support. Missing evidence uses null, not zero.
- Drive F1–F9 rules forbid automatic retries after uncertain creation and
  require provider proof, durable journal and an independently trusted CAS.
- OAuth validation remains loopback-only; a synthetic RS256/JWKS or PKCE
  exercise is not a real Auth0 login or ChatGPT pilot.
- The MCP resource and text fallback never carry literal source passages;
  HTML remains inert unless a trusted host delivers a valid snapshot.
- Four locale tags and all ten screens retain accessibility/focus
  constraints; dedicated browser tests remain mandatory.
- The distributable Skill ZIP excludes source-only CI/test tools,
  deployable MCP server and private project data.

## Limits
These are static and synthetic acceptance checks, not full browser/device
accessibility certification, security penetration testing, real user
isolation, semantic precision/recall, scientific evaluation, or external
service linearizability. Do not merge or deploy based solely on these checks.
