# Gate execution playbook — seven existing gates, human-controlled

Read scientific-governance.md, method profile, actual continuity and next_step_router.py first. The existing route-aware gate definitions and dependencies prevail. Tools listed are roles and alternatives, not mandatory vendor dependencies. Use real available tools; if none can fulfill a required operation mark blocked/NOT_RUN and do not mark READY. Read-only tool discovery and recommendations never approve gates. G1–G6 require attributable researcher reasoning and limitation where formative policy applies; G7 requires actual review and release authorization. No automatically approved gate, no silent scientific state changes.

| Gate | Authorized routine work and tool priority | Evidence before human review |
|---|---|---|
| G1 Question/contribution | Consult GitHub method cards; Consensus/Scite/academic web/OpenAlex locate close work and rival explanations; use actual original problem | Bounded novelty scan, nearest works, explicit problem, feasible contribution and limitations |
| G2 Method/protocol | Consult method cards/PDFs; adaptive_method_guide.py, method_choice_dialogue.py, method_fill_preflight.py; propose method-specific alternatives | Human route decision, protocol/design fields, sampling/selection logic, analytic plan, rights/ethics as applicable |
| G3 Search/positioning | Scopus/WoS when required and authorized; manual exports if unavailable; Crossref/OpenAlex for supplementary discovery, Consensus for terminology; keep literal searches and provenance | Real queries/exports and counts where required or route-specific theoretical positioning; no exhaustive search imposed on empirical design |
| G4 Corpus/data/materials | dedupe_records.py, doi_recovery.py, screening_review.py propose, Firecrawl/publisher, Unpaywall and abstract retrieval; empirical data audit or artefact trace as relevant | Reconciled eligible records or actual data/materials/artefact, human eligibility decisions, exclusions and rights/ethics; original occurrences preserved |
| G5 Synthesis/analysis | appraise_evidence.py, appropriate analysis tools/Python, corpus map when relevant, Scite for context; route-specific qualitative, quantitative, mixed, theory or DSR evaluation | Actual analysis, evidence provenance, counter-evidence, limitations and route-specific results; no invented results |
| G6 Claims/audit | verify_sources.py, claim_integrity.py, source_report_integrity.py, Crossref/registry/publisher, Scite for context, original sources | Actual source identity and semantic appraisal distinct; [L]/[I]/[P], claim links, counter-evidence, bounded originality and recorded independent judgment |
| G7 Submission | Fetch official journal instructions using native web/Firecrawl; sanitize_metadata.py, audit_anonymization.py, editorial_ai_disclosure.py, validate_project.py | Exact outgoing files inspected, references checked, truthful AI disclosure, applicable journal/rights/ethics checks, human release decision |

Before each gate, present concise current evidence, missing requirements, available tools and fallback, and next meaningful A/B/C/D decision if one remains. Do not bypass a previous gate, treat a task as approval, or demand a fake three-choice menu when only routine work remains. At gate transition run existing governance_events.py / gate_snapshot_transaction.py where applicable and available, with actual recorded human authorization, and re-read canonical state. No scripts available: use authorized native equivalent and disclose what was not executed. Continue autonomously within existing authorization until a real decision/blocker, and checkpoint. A completed gate is not evidence of scientific validity by itself.
