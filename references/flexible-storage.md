# Drive-first flexible storage and continuity

Use one canonical workspace; never silently fork an existing Drive project. Prefer Google Drive, explicitly offer its connection, verify actual access, and recheck after authorization. If unavailable, explain continuity risk and offer A/B/C/D: A reconnect Drive, B choose another authorized persistent store or Work workspace, C use an authorized local folder or downloadable checkpoint, D researcher proposal. Recommend Drive when feasible. A user's explicit named fallback request is sufficient for the storage choice; do not ask twice. A menu selecting an option with multiple destinations still needs the actual destination. A denial of Drive is not consent to a fallback.

Maintain existing storage_policy=GOOGLE_DRIVE_FIRST and storage_mode=WORK_FALLBACK for non-Drive temporary canonical work (to retain compatibility); record the actual provider/path or export filename, actor, authorization timestamp and persistence limitations in PROJECT_CONFIG.json and canonical CONTINUIDADE.md using existing records. Use the existing init_project.py --storage-mode WORK_FALLBACK --fallback-authorized-by (and timestamp) only when a real filesystem executor exists. Alternative connected provider may store the same tree; confirm its actual write/read capabilities and record actual backend in continuity, not fictitious Drive sync. Do not claim a provider is natively supported by local scripts merely because files can be exported/imported.

Local HD is available only in an environment exposing authorized user filesystem access; verify a chosen directory, never scan the entire disk, never assume a cloud sandbox is the user's HD. Work/cloud sandbox outputs may be temporary. If no persistent connector or local filesystem is available, create an explicit portable checkpoint export only if authorized and possible, including canonical tables, CONTINUIDADE.md, project config, source identifiers and checksums. Deliver actual link and instruct the user to save it and reattach before resumption; distinguish export produced from download/save verified. If no file executor exists, provide a clearly labeled manual handoff and do not assert persistent storage. Never export restricted full text or sensitive data without authorization.

For an existing project whose canonical store is unavailable, offer read-only help or obtain an explicitly authorized snapshot/staging copy; do not change canonical authority without actual reconciliation. On reconnect verify project identity, compare baseline/version and hashes, reconcile conflicts with researcher, preserve all DEC/TRACE/SNAP/GATE values and raw sources, then migrate with verified writes/read-back. Keep fallback history. Do not overwrite either divergent branch. Reoffer Drive at a meaningful resumption/migration opportunity, not every message. Do not approve any gate from storage migration.
