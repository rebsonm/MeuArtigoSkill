# RC.5 operational contract — read at activation and resumption

This contract refines interaction and execution, not scientific approval. Preserve existing projects, gate definitions, DEC/TRACE/SNAP IDs, raw exports and canonical state. No new mandatory tables or gates. Apply it in normal chat and Work whenever host capabilities permit; scripts in the package are not automatically executable tools.

## First response and resumption

Inspect current host tools and actual access. Surface the connection/install controls supported by the host for Google Drive, Consensus, Scite and Firecrawl when missing and relevant; explain one benefit and a fallback per tool. Offer optional SciSpace, Semantic Scholar, Zotero, TinyFish or equivalent only when useful. Do not invent links, permissions, connectors or API keys, require paid subscriptions or repeat a declined connection at every turn. Crossref and public metadata lookup need no proprietary plugin if real authorized web/API access exists. Check actual provider limits; report not executed, denied, quota, network and partial separately. Never send private text or PDFs to a provider for metadata lookup.

Drive is strongly preferred. Prompt for connection, verify read and write independently using an authorized project operation or harmless test, then use a single authorized fallback choice if blocked. Do not stall informational help while access is resolved. For substantive project operations require authorized storage. See flexible-storage.md. Inspect capability roles in parallel with storage onboarding rather than delaying all advice. Recheck a failed connection once after user action. Reuse confirmed permissions and decisions; do not keep asking the same question.

On resume read the canonical continuity file and matrix, reconcile pending transactions, check last verified state, and identify the exact next action. Never create duplicate projects or override old decisions. A question about a pending decision does not clear it. Answer, then render the existing or updated A/B/C/D choice if still relevant. If user replies in free prose, classify it as an explicit choice, clarification, proposed alternative, authorized routine request, or changed scope. Interpret clear choices; preserve exact proposal and ask only necessary clarification. Never infer approval from 'next', 'continue', an unanswered menu or operational consent. Keep the D input and explicit submit visible; fallback to plain chat A/B/C/D if host cannot render controls. See decision-navigation.md.

## Work between decisions

Execute maximal feasible batches of authorized routine operations (metadata, deduplication proposals, abstract retrieval, triage recommendations, technical checks), without per-record prompts. Use persisted queue/status, stable record IDs, checkpoints after batches, real receipts, unchanged raw exports and bounded retries. Resume only remaining eligible records; report actual counts (processed, resolved, unresolved, blocked, not run). A technical failure is not a zero-result search or exclusion. Ask only at a consequential fork, conflict, cost/access boundary, or gate review. Do not invent asynchronous execution or results. Preserve human decisions and never auto-approve gates. At pauses save verified state or explicitly mark unsynchronized deliverables.

## Stage routing

Use gate-tool-playbook.md to choose tools by actual research route and gate. Use doi-recovery.md for absent or suspect identifiers and missing abstracts. Use bibliometric-design.md when bibliometric mapping is relevant, under the existing appropriate review or quantitative route; it is not an automatic ninth route or mandatory analysis. Consult actual methodological cards/PDFs selectively via existing GitHub workflow. Separate consultation, discovery, DOI matching, full-text retrieval, semantic appraisal and scientific approval. Do not claim validation of the method or host from static package tests.
