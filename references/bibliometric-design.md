# Bibliometric design profile (existing routes)

Bibliometrics is an analytic strategy, not an automatic standalone scientific method. Select and justify the existing QUANTITATIVE (descriptive/associational) or appropriate review route based on the actual question; combine with a review only if each component is designed and justified. Do not silently migrate historical method profiles or gate IDs.

G1: define unit of analysis, bounded contribution and question. G2: specify corpus scope, databases, coverage window, search/filter protocol, unit (documents/authors/sources/institutions), disambiguation, indicators and denominators, counting approach (full/fractional), network type and thresholds, normalization, software/version, missing data and sensitivity plan. G3: use actual authorized indexed exports; record literal syntax and counts; preserve raw occurrences and database overlap. G4: deduplicate conservatively, recover DOI and metadata, reconcile author/affiliation variants, retain original fields and coverage limitations. G5: execute actual analysis (e.g. bibliometrix/Biblioshiny, VOSviewer, Python or R where available), document parameters, cleaning, counts and reproducibility, sensitivity to thresholds and coverage; never fabricate maps or metrics. G6: audit sources, indicators and inference; citation counts are not research quality and clusters are not independently validated theoretical constructs. G7: archive reproducible scripts/data when rights permit and disclose AI role. Use existing gates and tables; do not add mandatory sheets. No universal requirement for specific software. If software unavailable offer authorized equivalent or manual analysis; never claim execution.
