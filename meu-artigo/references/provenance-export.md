# W3C PROV and RO-Crate export

## Purpose

Meu Artigo uses W3C PROV and RO-Crate as an **interoperability/export layer**, not as a user-facing requirement.

The researcher continues to work through the canonical spreadsheet, C.A.D.A., traceability, evidence, and claims. When requested or at a major freeze/submission point, the project can export a machine-readable provenance package.

Official references:

- W3C PROV-O: https://www.w3.org/TR/prov-o/
- PROV namespace: http://www.w3.org/ns/prov#
- RO-Crate 1.3: https://w3id.org/ro/crate/1.3
- RO-Crate context: https://w3id.org/ro/crate/1.3/context
- RO-Crate specification: https://www.researchobject.org/ro-crate/specification/1.3/

Do not claim conformance to a specialized RO-Crate profile unless the project actually satisfies that profile.

## Export artifacts

The canonical export produces:

```text
RO_CRATE_<project>_<timestamp>/
├── ro-crate-metadata.json
├── manifest-sha256.txt
├── provenance/
│   ├── prov.jsonld
│   ├── provenance-report.json
│   └── PROVENANCE_REPORT.md
└── payload/
    ├── CONTINUIDADE.md
    ├── PROTOCOLO.md
    ├── RASTREABILIDADE.md
    ├── PROJECT_CONFIG.json
    ├── MATRIZ_MESTRA_*.xlsx
    ├── canonical CSV/log files
    └── canonical manuscript/submission files when available
```

A ZIP package is generated from that directory.

Full-text PDFs are excluded by default because they may contain licensed/copyrighted material. Include them only when the user explicitly intends to package them and has the right to do so.

## W3C PROV mapping

Use PROV-O concepts wherever they fit.

### Scientific governance mapping

- DEC_ID → `prov:Entity` representing a material scientific decision;
- GATE_ID → `prov:Activity` representing a human validation action;
- SNAP_ID → `prov:Entity` representing a frozen project state;
- validator/researcher → `prov:Agent`.

A decision may `prov:wasDerivedFrom` linked Evidence_IDs. A snapshot may `prov:wasGeneratedBy` its gate activity and `prov:wasDerivedFrom` the previous snapshot.

### Entity

Examples:

- bibliographic records;
- evidence items;
- claims;
- protocol/manuscript/export files;
- generated reports.

Represent as `prov:Entity`.

### Activity

Examples:

- TRACE events;
- database searches;
- validation actions;
- synthesis actions;
- provenance export.

Represent as `prov:Activity`.

### Agent

Examples:

- human researcher;
- AI system/tool;
- script;
- database/service.

Represent as `prov:Agent` or a specialized agent type when appropriate.

### Relationships

Use:

- `prov:used` — activity used an entity;
- `prov:wasGeneratedBy` — entity was generated by an activity;
- `prov:wasAssociatedWith` — activity involved an agent;
- `prov:wasDerivedFrom` — entity/claim derived from another entity/evidence.

Meu Artigo-specific relationships may use a custom namespace when PROV-O has no direct simple relation, for example linking a TRACE activity to a C.A.D.A. plan.

## RO-Crate 1.3

Generate `ro-crate-metadata.json` as JSON-LD.

Required base structure:

- metadata descriptor:
  - `@id = ro-crate-metadata.json`;
  - `@type = CreativeWork`;
  - `conformsTo = https://w3id.org/ro/crate/1.3`;
  - `about = ./`.
- root data entity:
  - `@id = ./`;
  - `@type = Dataset`;
  - descriptive name;
  - `hasPart` references to packaged files.

Use RO-Crate 1.3 context:

`https://w3id.org/ro/crate/1.3/context`

Describe AI tools/scripts as contextual entities where useful.

The separate `provenance/prov.jsonld` carries the richer PROV-O graph.

## Fixity

Generate `manifest-sha256.txt` containing SHA-256 checksums for packaged files except the manifest itself.

Purpose:

- detect later file changes;
- support preservation;
- allow independent verification that the package is unchanged.

A checksum proves file fixity, not scientific correctness.

## Export report

Generate:

- `provenance/provenance-report.json`;
- `provenance/PROVENANCE_REPORT.md`.

Report:

- export timestamp;
- standards/versions;
- trace-event count;
- PROV entity/activity/agent counts;
- RO-Crate file count;
- claims without evidence;
- DONE C.A.D.A. items without completion evidence;
- substantive AI use pending human validation;
- executed searches without literal query;
- other provenance gaps.

## Export moments

Offer/generate a package when:

- methodology/protocol is frozen and the user wants a snapshot;
- corpus/synthesis is frozen;
- manuscript version is frozen;
- immediately before/after submission;
- reviewer/editor requests provenance;
- user explicitly asks for an audit package.

Do not generate on every trivial change.

## Scientific caution

Interoperable provenance does not itself prove validity, rigor, or reproducibility.

It demonstrates that the construction process is documented in a standardized, inspectable form.

The scientific argument must still be evaluated on method, evidence, analysis, reasoning, and human responsibility.
