# Corpus Map

## Purpose

The Corpus Map answers:

> How is the validated literature corpus intellectually and structurally organized?

It complements, rather than replaces, search provenance, screening, evidence extraction, synthesis, and claims.

Corpus mapping is **exploratory by default**. Do not call the study bibliometric merely because the Skill visualizes authors, journals, years, concepts, citation links, clusters, or bridge records.

## Entry condition

Build the map only after there is a nontrivial retained corpus.

Prefer records classified as FULL TEXT — CORE or FULL TEXT — SUPPORT, or another explicitly included canonical status appropriate to the study design.

Do not map excluded records as if they belong to the scientific corpus.

## Canonical outputs

When filesystem execution is available, generate:

```text
04_Evidencias_e_Sintese/
├── MAPA_CORPUS.json
└── MAPA_CORPUS.md
```

The workbook exposes the human-facing view in `20_MAPA_CORPUS`.

## Data sources

Use only metadata actually available. Possible fields include Record_ID, title, authors, year, journal/source title, keywords, DOI, persistent identifier, OpenAlex ID, citation links, and concepts/topics.

Optional enrichment may use OpenAlex, Crossref, or an equivalent scholarly metadata source when available.

Record enrichment coverage explicitly. Do not fabricate missing journal, keyword, citation, or OpenAlex metadata.

## Map sections

Expose, where supported:

- corpus overview;
- publications by year;
- top authors;
- top source titles;
- top keywords/concepts;
- cluster summary;
- bridge records;
- metadata/enrichment coverage;
- map generation timestamp;
- method/edge definition;
- warnings.

Keep source-derived keywords and researcher-created analytical categories distinct.

## Citation structure

When citation relations are available, the map may show highly cited records, citation-connected components, bridge records, and isolated records.

Do not infer citation links from semantic similarity.

## Clusters

Only create network clusters when there is an actual edge model such as citation, coauthorship, bibliographic coupling, co-citation, or keyword co-occurrence.

Label the edge definition explicitly.

A semantic grouping generated by an LLM is not automatically a bibliometric cluster.

## Bridge records

A bridge label must state the operational basis, such as graph betweenness or connection across otherwise separate communities.

Do not call a paper a bridge solely because it "seems interdisciplinary."

## Provenance

A corpus-map generation is a material process event. Record TRACE_ID, input corpus state/SNAP_ID when available, metadata sources, enrichment date, algorithm/rule, outputs, warnings, and coverage.

If AI materially interprets clusters or labels, also record AI_Use_ID and human review.

## Reference implementation

Use `scripts/build_corpus_map.py`.

The script must operate with available metadata and degrade gracefully when optional bibliometric fields are absent.
