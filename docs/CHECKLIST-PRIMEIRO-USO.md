# Checklist de primeiro uso — beta pública

Utilize este roteiro para orientar o primeiro contato. Ele **não** substitui os gates reais e não é um formulário de pesquisa.

- [ ] Obtive a versão identificada no GitHub Releases e conferi o ZIP/manifest quando aplicável
- [ ] Minha plataforma oferece importação da Skill; confirmei que `SKILL.md` está na raiz
- [ ] Defini o problema e os objetivos do novo artigo, sem copiar dados de outro projeto
- [ ] Conectei o Google Drive com autorização ou autorizei expressamente um fallback documentado
- [ ] Informei revista-alvo e instruções oficiais, se disponíveis; caso contrário, comecei em modo neutro
- [ ] Decidi o desenho de pesquisa com base no problema, sem tratar toda revisão como sistemática
- [ ] Autorizei apenas buscas e acesso a fontes que realmente posso utilizar
- [ ] Registrei consultas reais, decisões de seleção, revisões e pendências sem valores fabricados
- [ ] Mantive o C.A.D.A. como gestão operacional, distinto de aprovação científica
- [ ] Conferi a base jurídica dos PDFs antes de redistribuição e apliquei a auditoria de anonimização
- [ ] Registrei, quando aplicável, o uso de IA e conferi a política editorial antes do envio
- [ ] Identifiquei limitações, dependências externas e ações que permanecem pendentes

Se o procedimento falhar, registre a versão da Skill, a plataforma e a etapa específica, retirando qualquer dado pessoal ou documento confidencial. O uso deste checklist não comprova validação empírica nem entendimento científico.
